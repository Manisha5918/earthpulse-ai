# EarthPulse AI — Dedicated Dataset Repository

This directory serves as the centralized, immutable storage and documentation repository for all external datasets collected, ingested, and processed for **EarthPulse AI**.

---

## 1. Purpose of the Repository

EarthPulse AI combines heterogeneous earth observation, meteorological, and geospatial context datasets onto a common analytical grid (0.05° fishnet) and timeline. 

The `datasets/` repository guarantees:
1. **Scientific Reproducibility**: Exact raw API responses and satellite metadata are archived in their original form.
2. **Auditability & Traceability**: Every metric in EarthPulse AI can be traced back to its specific source URL, product granule ID, acquisition timestamp, and sensor characteristics.
3. **Data Integrity**: Raw external observations are strictly immutable and never altered after collection.
4. **Clean Separation**: Code, models, and application logic are separated from physical datasets.

## 2. Directory Architecture

The repository is partitioned by source provider, with each source maintaining three distinct tiers:

```
datasets/
├── README.md                  # Dataset repository documentation & provenance rules
│
├── nasa_power/                # NASA POWER Solar & Meteorological Data
│   ├── raw/                   # Unmodified raw JSON API responses from NASA Langley
│   ├── processed/             # Cleaned daily CSVs, JSON, and PostGIS observations ledger
│   └── metadata/              # Licensing, variables, coordinates, and endpoint metadata
│
├── sentinel2/                 # ESA Copernicus Sentinel-2 Level-2A Surface Reflectance
│   ├── raw/                   # STAC catalog query responses & scene metadata
│   ├── processed/             # Calculated NDVI, NDWI, NDBI grid metrics & observations ledger
│   └── metadata/              # Band definitions, formulas, SCL cloud mask classes, and CRS
│
├── viirs/                     # NOAA VIIRS Day/Night Band Nighttime Lights (Phase 3)
│   ├── raw/                   # Raw nocturnal radiance composites (.tif / .h5)
│   ├── processed/             # Grid-aggregated nocturnal radiance metrics
│   └── metadata/              # Calibration parameters, cloud screening flags, sensor specs
│
└── osm/                       # OpenStreetMap Spatial Infrastructure (Context)
    ├── raw/                   # Overpass API GeoJSON query extracts
    ├── processed/             # Spatial density & distance metrics per grid cell
    └── metadata/              # Tagging schema, query filters, and ODbL attribution
```

## 3. Distinction: Raw vs. Processed vs. Metadata

| Tier | Directory | Definition & Scope | Mutability Rule |
| :--- | :--- | :--- | :--- |
| **Raw** | `datasets/<source>/raw/` | Exact byte-for-byte responses, STAC feature collections, and raster granules retrieved directly from external APIs/catalogs. | **IMMUTABLE**. Never silently edited, filled, or modified. |
| **Processed** | `datasets/<source>/processed/` | Cleaned, validated, quality-masked, and spatially aggregated outputs generated by EarthPulse's deterministic ETL pipeline. | **REPRODUCIBLE**. Fully regenerated by executing `scripts/`. |
| **Metadata** | `datasets/<source>/metadata/` | Machine-readable JSON specifications documenting licensing, CRS, native spatial/temporal resolution, algorithms, formulas, and sensor characteristics. | **AUDITABLE**. Version-controlled documentation. |

## 4. Strict Data Provenance Rules

EarthPulse AI strictly enforces a four-tier provenance contract:

### 1. `OBSERVED`
- **Definition**: Physical measurements directly captured by remote sensing satellites, meteorological weather stations, or ground instruments.
- **Rule**: Must contain exact sensor timestamp, source URL, dataset identifier, and physical units. Zero fabrication permitted.
- **Examples**: NASA POWER Daily Temperature (`T2M`), Precipitation (`PRECTOTCORR`), Sentinel-2 BOA Surface Reflectance (`B04`, `B08`, `B03`, `B11`).

### 2. `CALCULATED`
- **Definition**: Quantitative indices, statistical metrics, or spatial aggregations derived deterministically from `OBSERVED` data by our own processing algorithms.
- **Rule**: Must document the exact mathematical formulation, input bands, and processing timestamp. Missing data must never be silently filled.
- **Examples**: NDVI `(NIR - RED) / (NIR + RED)`, NDWI `(GREEN - NIR) / (GREEN + NIR)`, NDBI `(SWIR1 - NIR) / (SWIR1 + NIR)`, 3-year rolling median/MAD baselines, robust z-scores.

### 3. `AI_INTERPRETED`
- **Definition**: Explanations, causal hypotheses, or natural language briefings synthesized by machine learning models or LLMs.
- **Rule**: Must strictly cite underlying `CALCULATED` or `OBSERVED` evidence IDs. Cannot invent metrics or percentages.

### 4. `SYNTHETIC_DEMO`
- **Definition**: Explicitly simulated mock values used only for offline UI layout validation or unit test suites.
- **Rule**: Must NEVER be mixed into `datasets/`. Permitted only in opt-in testing utilities (`scripts/seed_demo.py`) with visible UI disclaimer banners.

## 6. Immutable Raw Data Rule

> [!CAUTION]
> **Raw external data must never be silently modified, interpolated, or imputed.**
> - If an API request fails or an observation is missing, the record must be marked `NaN` / `NULL`.
> - If cloud cover obscures an optical satellite pixel, the pixel must be masked using the Scene Classification Layer (`SCL`) rather than imputed with fake values.
> - Any interpolation or temporal smoothing must occur strictly in the `CALCULATED` stage and be recorded with transparent algorithm flags.
